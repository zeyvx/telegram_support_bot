# Telegram Support Bot
 
Telegram-бот службы поддержки: регистрация пользователей, приём заявок с категориями и вложениями, а также полноценная обработка заявок администраторами — от взятия в работу до ответа пользователю или отклонения с указанием причины.
 
Проект написан на Python с использованием асинхронного фреймворка **aiogram 3** и асинхронной работы с **SQLite** (aiosqlite).
 
## Возможности
 
### Пользователь
 
- Регистрация через отправку контакта Telegram
- Выбор категории обращения:
  - Техническая проблема
  - Оплата
  - Доставка
  - Заказ
  - Другое
- Создание заявки с текстовым описанием проблемы
- Прикрепление документа или фотографии (или пропуск этого шага)
- Просмотр собственных заявок с постраничной навигацией (inline-кнопки)
- Просмотр категории, описания, статуса и причины отказа (если заявка отклонена)
- Получение ответа администратора и уведомления об отклонении заявки прямо в чат
- Быстрая связь с оператором и раздел FAQ (заглушка)
### Администратор
 
- Отдельная панель, которая открывается автоматически, если ID пользователя есть в списке администраторов
- **Новые заявки** — список заявок со статусом `Новая`, постраничная навигация, кнопки «Взять в работу» и «Отклонить» прямо из списка
- **Мои заявки** — заявки, взятые администратором в работу (статус `В работе`); список открывается как нумерованное меню, по номеру можно открыть карточку конкретной заявки
- **Все заявки** — просмотр всех заявок вне зависимости от статуса, с постраничной навигацией
- **Статистика** — сводка по количеству заявок в каждом статусе (новые / в работе / завершены / отклонены)
- Действия над открытой заявкой:
  - ✅ Завершить (статус → `Завершена`)
  - 💬 Ответить пользователю (сообщение уходит пользователю напрямую от бота)
  - 🔄 Вернуть в очередь (статус → `Новая`, заявка откреплена от админа)
  - ❌ Отклонить с указанием причины (статус → `Отклонено`, причина сохраняется и отправляется пользователю)

## Описание основных компонентов
 
### `handlers/`
 
Обработчики сообщений, команд и callback-запросов Telegram, разделённые на пользовательскую и административную часть.
 
- `handlers/user/start.py` — регистрация, приветствие, FAQ, связь с оператором.
- `handlers/user/requests.py` — создание заявки (категория → описание → файл/пропуск), просмотр своих заявок.
- `handlers/admin/admins.py` — списки заявок (новые / все / мои) и статистика.
- `handlers/admin/requests.py` — точечные действия над конкретной заявкой (взять, завершить, вернуть в очередь, ответить, отклонить с причиной).
### `database/`
 
- `database.py` — создание и инициализация таблиц `users` и `requests` при первом запуске.
- `dao/users_dao.py` — регистрация пользователей, создание заявок, получение заявок конкретного пользователя.
- `dao/admins_dao.py` — выборка новых/всех заявок, заявок конкретного админа, взятие в работу, завершение, возврат в очередь, отклонение с причиной, агрегированная статистика по статусам.
### `keyboards/`
 
- `user.py` — главное меню пользователя, выбор категории, кнопка «Пропустить».
- `admin.py` — стартовое меню админа, клавиатура действий над открытой заявкой, список «Мои заявки».
- `navigation.py` — переиспользуемая inline-пагинация для списков заявок; на страницах «Новые заявки» дополнительно добавляет кнопки «Взять в работу» и «Отклонить».
### `states/`
 
FSM-состояния сценариев бота:
 
```
Регистрация:
waiting_contact
 
Создание заявки:
category → request → file
 
Действия администратора:
waiting_for_reply           # ожидание текста ответа пользователю
waiting_for_cancel_reason   # ожидание причины отклонения заявки
```
 
### `utils/`
 
`requests_utils.py` — форматирование текста заявки для карточки (с причиной отказа, если есть), краткого представления в списках и текста статистики.
 
## База данных
 
Проект использует SQLite (файл `database.db`, создаётся автоматически при первом запуске, включён `PRAGMA foreign_keys = ON`).
 
### Таблица `users`
 
| Поле      | Описание                      |
| --------- | ------------------------------ |
| `user_id` | Telegram ID пользователя (PK) |
| `phone`   | Номер телефона (уникальный)   |
 
### Таблица `requests`
 
| Поле       | Описание                                             |
| ---------- | ------------------------------------------------------ |
| `id`       | Уникальный ID заявки (PK, автоинкремент)              |
| `user_id`  | ID пользователя, создавшего заявку (FK → `users`)     |
| `category` | Категория обращения                                   |
| `request`  | Описание проблемы                                     |
| `file_id`  | Telegram file_id вложения (может быть `NULL`)         |
| `status`   | Текущий статус (`Новая`, `В работе`, `Завершена`, `Отклонено`) |
| `admin_id` | ID администратора, взявшего заявку в работу / отклонившего её |
| `reason`   | Причина отказа (заполняется только при отклонении)    |
 
## Установка
 
### 1. Клонирование репозитория
 
```
git clone https://github.com/zeyvx/telegram_support_bot.git
cd telegram_support_bot
git checkout feature/request-actions
```
 
### 2. Создание виртуального окружения
 
**Windows**
 
```
python -m venv .venv
.venv\Scripts\activate
```
 
**Linux/macOS**
 
```
python3 -m venv .venv
source .venv/bin/activate
```
 
### 3. Установка зависимостей
 
```
pip install -r requirements.txt
```
 
### 4. Настройка переменных окружения
 
Создайте файл `.env` в корне проекта на основе `.env.example`:
 
```
BOT_TOKEN=your_bot_token
OPERATOR_PHONE=your_operator_phone
ADMIN_IDS=your_admin_telegram_id
```
 
Файл `.env` не должен попадать в git (уже добавлен в `.gitignore`).
 
> ⚠️ На данный момент `ADMIN_IDS` поддерживает только один Telegram ID администратора — значение оборачивается в список из одного элемента (`config.py`). Для нескольких администраторов потребуется доработка парсинга переменной.
 
### 5. Запуск
 
```
python main.py
```
 
## Сценарий работы пользователя
 
```
/start
   │
   ├── Пользователь уже зарегистрирован → Главное меню
   │
   └── Не зарегистрирован → Отправка контакта → Регистрация → Главное меню
```
 
Создание заявки:
 
```
Отправить заявку → Выбор категории → Описание проблемы
   → Документ / фото / "Пропустить" → Заявка сохранена
```
 
## Сценарий работы администратора
 
```
/start (ID есть в config.ADMINS)
   │
   └── Панель администратора
         ├── Новые заявки → пагинация → "Взять в работу" / "Отклонить"
         ├── Мои заявки (взятые в работу) → открыть заявку → действие
         │       ├── ✅ Завершить
         │       ├── 💬 Ответить пользователю
         │       └── 🔄 Вернуть в очередь
         ├── Все заявки → пагинация
         └── Статистика
```
 
Отклонение заявки (из списка «Новые заявки»):
 
```
"Отклонить" → Ввод причины текстом → Статус → "Отклонено"
   → Пользователю приходит уведомление с причиной
```
 
## Архитектура проекта
 
Проект придерживается разделения ответственности между слоями:
 
```
Telegram Update
      ↓
   Handler
      ↓
     DAO
      ↓
   Database
```
 
- `handlers` — приём и обработка апдейтов Telegram, включая FSM-сценарии.
- `dao` — работа с базой данных (SQL-запросы).
- `database` — инициализация базы и таблиц.
- `keyboards` / `utils` — вспомогательные слои: генерация клавиатур и форматирование текста.
## Git-ветки
 
```
main
│
└── feature/request-actions
```
 
`main` содержит стабильную версию проекта. Данная ветка (`feature/request-actions`) добавляет полный набор действий администратора над заявкой: завершение, возврат в очередь, ответ пользователю и отклонение с указанием причины.
